# FXID - файл эффектов

Заголовок 0x3C + `count` компонентов подряд. Размеры компонентов и смещения ссылок на материал проверены на 476 файлах / 1567 компонентах из NRes-архива `effects.rlb`.
Код: `Effect.dll`, `EffectHandle::InitFromFxidData`. Типизированное чтение: `FxidLib/FxidFile.cs` (`FxidFile.Read`), перечисления: `FxidLib/FxidEnums.cs`.

```
0x00 count
0x04 StrengthSource (EEffectStrengthSource, откуда берётся "сила" эффекта 0..1)
0x08 Duration, секунды (0.0 разрешён только для источников, не завязанных на жизнь)
0x0C StrengthJitter (амплитуда, работает с флагом 0x1)
0x10 Flags
0x14 SettingsId (младший байт 0..19 - категория эффекта, индекс в таблице включения по пресету детализации (`GetDust`), значение 0 в таблице = эффект не создаётся; второй байт 0..3 - класс LOD частиц: пороги `rand*D[класс]-H[класс]` против уровня качества рендера)
0x18 RandShift (амплитуда случайного смещения позиции, флаг 0x8)
0x24 Pivot (Vector3)
0x30 Scale (Vector3)
0x3C компоненты
```

Флаги (проверены по коду):

```
0x0001 RandomizeStrength    сила += случайное в пределах StrengthJitter
0x0002 AutoDeleteAtFull     удалить эффект, когда сила достигла 1
0x0004 DetachAfterEmit      отвязать от точки привязки после обновления
0x0008 RandomOffset         случайное смещение позиции (RandShift)
0x0010 AlwaysEnabled        игнорировать состояние детали
0x0020 TriangularShape      сила v -> (v>=0.5 ? 1-v : v)*2
0x0040 StartInactive        эффект создаётся неактивным
0x0080 OnlyWhenEnvBit0On    сила 0, пока бит 0 окружения сброшен (ни в одном из 476 файлов не встречается)
0x0100 OnlyWhenEnvBit0Off   сила 0, пока бит 0 окружения установлен
0x0200 MultiplyByLife       сила *= прогресс жизни
0x0400 HideWhenOccluded?    периодический луч до ближайшей грани; рисуется только если луч чист
0x0800 RenderOnlyInExtraPass?
0x1000 TracksAttachPoint?
0x2000 ?                    бит 13 передаётся в рендер компонентов (в частицах) - смысл неизвестен
0x8000 EnabledInAnyPieceState
```

Рендер эффекта (`EffectHandle::RenderEffectComponents`): отсечение по сфере видимости (6 плоскостей фрустума), затем `CShade::ComputePrimitiveLodFromSphere(камера, сфера, логический тип владельца)` даёт уровень качества 0..7 (0 - лучший, >=8 - не рисовать). Этот же уровень уходит компонентам как `render_ctx[0x18]` и сравнивается с LOD-порогом частиц. Проверка окклюзии (флаг 0x400): луч от камеры до pivot, повтор через `g_settings+0x14A4` мс (50/250/1000 для пресетов 1/2/3) с разбросом +-12.5% - это **интервал перепроверки видимости, а не дальность прорисовки**.

Флаги состояния `EffectHandle.stateFlags` (рантайм, не из файла; начальное значение 0x40):
```
0x01 SettingsEnabled   ставится в EvaluateComponentsAndMergeBounds, если GetDust(SettingsId) != 0; без бита эффект не рисуется
0x08 NotOccluded       результат луча окклюзии (1 = луч чист)
0x10 PeriodicCheck     header-флаг 0x400 ИЛИ бит 8 TypeAndFlags любого компонента: включает периодический луч
0x20 RestartPending    если end_time <= now: start=now, end=now+duration, бит снимается (перезапуск; кто ставит - не найдено)
0x40 KeepUpdating      "недавно нужен": пока бит стоял / now < next_update, эффект считается каждый кадр, иначе раз в 100 мс; рендер ставит бит, когда эффект в зоне (LOD < 8)
0x100 OcclusionCulling header-флаг 0x400: рисовать только если 0x08
```
Условие отрисовки: `(state & 0x08) || !(state & 0x100)`. Биты 0x02, 0x04, 0x80 в изученных функциях EffectHandle не используются.

Источники силы: по времени жизни (`Life_0to1`, `Life_Fract`, `Life_1minus`), по прогрессу анимации детали, по скорости (`TangSpeed*`, `NormSpeed*`), по состоянию системы жизни (`LifeSystemInvX`) и по свойствам `IControl`. Результат кладётся в `EffectHandle.currentStrength` и передаётся компонентам во втором слове контекста.

### Компоненты

Каждый компонент начинается с `TypeAndFlags` (младший байт - тип 1..10, бит 8 копируется в байт +4 рантайм-объекта). В таблице: размер блока в файле, смещение ссылки на материал/ресурс, рантайм-класс и роль.

| Тип | Блок | Ссылка | Класс | Роль |
|---|---|---|---|---|
| 1 | 0xE0 | 0xA0 | EffectType1 (0xF0) | динамический источник света (ILightManager) |
| 2 | 0x94 | 0x54 | EffectType2 (0xA0) | 3D-звук |
| 3 | 0xC8 | 0x88 | EffectType3 (0xFC) | анимированный объект (EffectContents) |
| 4 | 0xCC | 0x88 | EffectType4 (0x104) | как 3, плюс масштаб по расстоянию (+0xC8, float 150/300/500/700) |
| 5 | 0x70 | 0x30 | EffectType5 (0x54) | шлейф между предыдущей и текущей точкой привязки |
| 6 | 0x04 | - | (0x1C) | пустой компонент, ничего не делает (ни в одном из 476 файлов не встречается) |
| 7 | 0xD0 | 0x90 | EffectType7 (0x48) | эмиттер частиц (частица 0xCC, без цикла) |
| 8 | 0xF8 | 0xB8 | EffectType8 (0xAC) | спавнер частиц вдоль пути точки привязки |
| 9 | 0xD0 | 0x88 | (0x100) | как 3, другой рендер; после ссылки два dword: режим отрисовки (0/1, код знает 0..2) и флаг (0/1) |
| 10 | 0xD0 | 0x90 | EffectType10 (0x48) | эмиттер частиц (частица 0x1EC, с циклом) |

Ссылки типов 3, 4, 7-10 указывают на материалы (`material.lib`), загрузка идёт через `FxManager::GetOrLoadMaterialHandle`. Ссылка типа 5 тоже материал, типа 2 - wave-файл.

Общее для всех компонентов (слоты vtable `IEffect`): 0 деструктор, 1 `SetParams`, 2 `EvaluateAtTime`, 3 `Render`, 4 `GetTypeAndFlags`, 5 `OnEnabledChanged`, 6 `OnAttachPointMoved`, у 7/10 слот 7 - `GetParticle(index)`.
Контекст `EvaluateAtTime`: dword0 - секунды с начала, dword1 - значение силы 0..1 (окна активности компонентов сравниваются с ним), dword2-17 - копия родительской матрицы (позиция - 3-й столбец), dword18 - длительность.

#### Тип 3 (и 4, 9 - тот же префикс)

```

0x08/0x0C/0x10 фаза: начало, конец, степень (начало<0 -> фаза идёт по секундам ctx[0], иначе по нормированной жизни)
0x14/0x18/0x1C интерполяция "жизни" для рендера: начало, конец, степень
0x20/0x24 окно активности
0x28 PositionStart  0x34 PositionEnd  0x40 PositionExponent (покоординатно)
0x4C DirectionStart 0x58 DirectionEnd
0x64 ScaleStart     0x70 ScaleEnd     0x7C ScaleExponent
0x88 ResourceRef
```
Радиус границы = max компонента PositionStart/End + max |ScaleStart/End|.

#### Типы 7 и 10 (эмиттер частиц, одинаковая раскладка 0xD0)

```
0x04 Mode?  0x08/0x0C/0x10 value lerp (начало, конец, степень)?
0x14/0x18 окно активности (по значению силы; внутри окна нормируется в 0..1)
0x1C доля жизни одной частицы  0x20 скорость повторения
0x24 Groups  0x28 PerGroup (частиц Groups*PerGroup)
0x2C TrajectoryStart  0x38 TrajectoryEnd (+ случайный бокс)  0x44 SpawnBox  0x50 ColorExponent?
0x5C SizeStart  0x68 SizeEnd (только тип 7)  0x74 SizeJitterBox  0x80 SizeExponent?
0x8C GravityFactor?  0x90 ResourceRef
```
Группы стартуют со сдвигом `(1 - жизнь частицы) * i / Groups`; для частицы отсев по LOD-порогу (`NextRandLODValue`) против параметра качества рендера. Гравитация: сдвиг по третьей оси `g*t^2`. Тип 7 не зациклен, тип 10 зациклен и при неудачной загрузке материала берёт случайный.

#### Тип 8 (спавнер)

Тот же блок частицы, что и у 7/10, но смещён на +0x2C (с 0x58 по 0xB7), перед ним параметры спавна: окно 0x10/0x14, интервал спавна 0x18/0x1C, размер кольцевого буфера 0x24, смещение точки спавна 0x28/0x34/0x40 (+степень 0x4C). Ссылка на материал: 0xB8.

#### Тип 2 (звук)

```

0x08/0x0C окно  0x10..0x3F два вектора (начало/конец) 3D-параметров  0x48/0x4C скаляр (вероятно, громкость)
```

## EffectContents (общая часть типов 3, 4, 9)

Встроенный объект в рантайме (тип 3/9: `this+0x30`; тип 4: `this+0x38`), vtable `1001eaf8`. Заполняется в `EffectType3::SetParams` из компонента: `space` (+4 файла), `content_handle` = `GetOrLoadMaterialHandle(resource)`, позиция/направление/масштаб = `start + t * (end - start)` (хранятся `Start`, `Speed = end - start` и текущее значение).

Слоты vtable: 0 `RebuildWorldTransformMatrix(refPoint, parentTransform)`; 1 `Draw` (6 стековых аргументов: ctx[0], ctx[1], фаза 0..1, значение life-lerp, "виден" (byte [ctx+0x1a] && runtime byte +4), бит 13 флагов заголовка); 2/3 `AnimatePosition` ByValue/Scaled; 4/5 `AnimateDirection`; 6/7 `AnimateScale`; 8 `GetDrawFlagsParam(flags)` (возвращает указатель на статическую таблицу; flags: 2, +1 если "виден", +4 если бит 13).
`ByValue(t)`: `v = start + t*speed`; `Scaled(vec)`: покомпонентно `v = start + vec*speed`. `EffectType3::RenderContents` считает `life^exponent` по осям (степени из `position_exponent`, `direction`, `scale_exponent`) и вызывает `AnimatePositionScaled`, `AnimateDirectionByValue(life)`, `AnimateScaleScaled`; затем `Rebuild...` с опорной точкой `ctx[0x12..0x14]` и родительской матрицей `ctx+8`, затем `Draw`. Рисуется только при `life >= 0` и `quality < 8`.

`space` (ESpace, значение 3 в самом файле тоже допустимо):
- 0 `MESH` - свободный билборд: ось Z = нормаль на опорную точку (камеру), позиция из `position`. В файлах: тип 4 всегда 0, тип 3 - 76 раз.
- 1 `LOCAL` - осевой билборд: фиксированная ось `direction`, разворот к опорной точке вокруг неё. Тип 3 - 79 раз.
- 2 `WORLD` - обычная матрица из `direction` + `position`. Тип 9 всегда 2, тип 3 - 239 раз.
- 3 `WORLD|LOCAL` - ось по движению (`position - previousWorldPosition` в локальных координатах), разворот к опорной точке; ни в одном из 476 файлов не встречается.
Во всех режимах: `ApplyScale(scale)`, умножение на родительскую матрицу, колонка 3 = родитель * `position`. Если вырожденный случай (опорная точка совпадает с позицией/осью), `b_IsTransformValid = false` и `Draw` пропускается.

Тип 4: прогресс анимации = `clamp(расстояние_до_камеры / ReferenceDistance * life, 0..1)` (`EffectType4::RenderContents`; расстояние - длина опорного вектора, переведённого в локальные координаты эффекта). Т.е. +0xC8 - дистанция, на которой анимация завершена (150/300/500/700 в файлах).
Тип 9: поле `render_group` (+8 `EffectContents`) на самом деле слово флагов рендера: база 1 (типы 3/4) или 3/5/6 по DrawMode типа 9, биты 30-31 = уровень качества 0..3, 0x8000000 если Flag == 0.

## Режим частиц (`Mode`, +4)

Тип 7: 0 и 2 -> значение 0 в частице (+0xC), 1 -> 3 (режим отрисовки частицы, смысл значений - внутри рендерера). Частицы типа 7 - плоскости (0xCC байт).
Тип 10 (частицы 0x1EC байт - **случайные многогранники**): `Mode` 0x10 или 0x20 выбирает таблицу форм, форма для каждой частицы выбирается случайно (`FUN_1000caf0`, параметры - (вершины, треугольники)):
- Mode 0x10 (и любое другое значение): (4,4) 87.5%, (6,8) 10.9%, (8,12) 1.4%, (12,20) 0.2%; возвращаемый "уровень" 0/1/2/3.
- Mode 0x20: (4,4) 93.75%, (12,20) 3.1%, (18,32) 3.1%; уровень 1/3/3.
Возвращаемый уровень записывается в `lod_thresholds` частицы **поверх** значения от `NextRandLODValue`, т.е. у типа 10 LOD-порог частицы определяется сложностью формы, а класс LOD из `SettingsId` не используется (категория `SettingsId` работает как у всех).
Загрузка материала: если ресурс не найден (handle == -1), тип 10 берёт случайный материал из списка (`обшее число - 1`).

## Гравитация частиц и параметры звука

`GravityFactor` (+0x8C, типы 7/10/8): гравитация частицы = `GravityFactor * IWorld::QueryGravity() * 0.5` (см. `InitCommon`; слот 4 IWorld, +0x10). Просадка по третьей оси = `гравитация * t^2` (т.е. g*t^2/2).
Тип 2 (звук): смещение позиции и громкость линейно зависят от значения силы (`start + v*(end-start)`), позиция переводится матрицей родителя в мир; `MinDistance` и `MaxDistance` - константы (в `SetParams` нет интерполяции); векторы направления в `EvaluateAtTime` не читаются (только копируются в `SetParams`). Блок параметров (размер 0x48) уходит командой 0x38E в `I3DSound`, последнее поле блока - `Unknown50`; сфера границ эффекта читается обратно из этого же вызова.

## Значение "value" в вызове Draw (типы 5, 7, 8, 10, 3)

У всех компонентов с рисованием четвёртый аргумент `Draw` - линейно/степенно меняющееся значение (в файлах 1.0 -> 0..0.5, похоже на прозрачность): тип 3 - `life_lerp_start/end/exponent`, тип 7/10 - `+8/+0xC/+0x10`, тип 8 - `+4/+8/+0xC` (`start + pow(exponent, life)*(end - start)`), тип 5 - `+4/+8` по значению окна (без степени). Конкретное значение (альфа/яркость) задаётся рендерером. Поле +0x20 типа 8 в рендере возводится в степень, но результат отбрасывается.

### Как считается Strength (`ComputeEffectStrength`)

Life = (now − start) / (end − start). Затем:

- Если `OnlyWhenEnvBit0On` (0x80) и env-бит 1 выключен, либо `OnlyWhenEnvBit0Off` (0x100) и env-бит 1 включён, то Strength = 0.
- Источники: 0 — константа из `method6`; 1 — Life; 2 — дробная часть Life; 3 — 1−Life; 4 — прогресс анимации части (`GetPieceAnimTransitionProgress`); 5–8 — тангенциальная скорость (модуль / X / Y / Z) к пределу из `IControl`; 9–12 — то же для нормальной скорости; 13 — 1 − доля жизни (`ILifeSystem`); 14 — 1 − свойство 0x31 `IControl`; 15 — максимум из относительных тангенциальной и нормальной скоростей; 16 / 17 — прогресс анимации, зажатый снизу / сверху относительно прошлого значения.
- Постобработка: флаг 0x200 (`MultiplyByLife`) умножает на Life; флаг 0x20 (`TriangularShape`) превращает значение в треугольник: `v < 0.5 ? 2v : 2(1−v)`.
- Результат хранится в `EffectHandle.currentStrength`.

### Жизненный цикл `EffectHandle`

- `StartEffect(now, strengthSource)`: `start = now`, `end = now + Duration*1000`, **источник силы из вызова подменяет `StrengthSource` из файла**; `next_update = now + 50`.
- `RequestStopEffect(now)`: ставит `RestartPending` (0x20). Эффект не обрывается: когда `end <= now`, `EvaluateComponentsAndMergeBounds` перезапускает цикл (`start = now`, `end = now + Duration*1000`) и **возвращает `StrengthSource` из файла**. Название метода вводит в заблуждение.
- `SetActive(on, now)`: `elapsed = (now - start)/1000`, `next_update = now + 50`; при выключении компоненты вычисляются ещё раз.

### `EvaluateComponentsAndMergeBounds`

- Работает, если `now < next_update` или прошло ≥100 мс с прошлого вычисления; иначе пропускается.
- Если `GetDust(SettingsId) == 0` (детализация выключена), компоненты не вычисляются, сферы остаются нулевыми.
- Сила: `-1` — «без значения», иначе зажимается в 0..1. Флаг `RandomizeStrength` (0x1) для всех компонентов, кроме звука: `s' = clamp(s + StrengthJitter/2 − rand01·StrengthJitter, 0, 1)`. Звук получает силу без разброса.
- Флаг `RandomOffset` (0x8): к позиции мировой матрицы добавляется случайный сдвиг из `RandShift` (по каждой оси центрированный разброс шириной `RandShift`).
- Границы: у каждого компонента берётся сфера (центр, радиус); визуальные (все типы, кроме звука) и звуковые объединяются в две отдельные сферы (`bounds_sphere_visual`, `bounds_sphere_sound`). Итоговые радиусы умножаются на максимальный масштаб осей `parentTransform`.

### Как игра запускает эффекты

Эффекты запускают команды CTL (`Control.dll`, `ExecuteControlCommandList`), подробности и аргументы — в `ControlLib/README.md`. Коротко: spawn-команды (3/4/5) по имени элемента `effects.rlb` создают эффект и задают позицию/масштаб/матрицу (`LoadNResEffectItem`, `SetEffectScale/Position/Transform`); `START_EFFECT` передаёт источник силы (в 449 разобранных CTL: Life_0to1 — 147 раз, Constant — 30, Life_1minus — 4, Life_Fract — 3), `ATTACH_EFFECT_TO_PIECE` (`method11`) задаёт деталь, по анимации которой считаются источники 4/16/17. В данных CTL переопределение встречается только для источников 0–3; остальные (4, 5, 14–17 и т.д.) берутся из заголовка FXID.

### Кто ссылается на FXID

Из 476 элементов `effects.rlb` 206 запускаются spawn-командами CTL (`EffectUsage`). Остальные 270 (поиск имени по всем распакованным ресурсам и по DLL/EXE): 134 имеют ссылки в распакованных данных — из них 78 в EXPL (взрывы: ресурс `effects.rlb` + имя элемента), 77 в других местах CTL (в записях предметов, например двери и огни фортификаций; 23 имени есть и там и там), `env_lightning` — строка в `Terrain.dll` (молния атмосферы, см. ниже), `env_mineral` — в коде `iron3d.dll` (push адреса строки по 0x100931a1), ещё 29 — только в `.rlb`-архивах игры, не распакованных в `ParkanUnpacked`, и 107 нигде не названы по имени (в основном цветовые варианты огней `*_balllight_*`, `*_blinklight_*`, `*_signlight_*`, `*_smalllight_*`, `exp_*` и `selfexp_*`; вероятно, неиспользуемые или собираемые из частей имени).

### EXPL: взрыв выбирает эффект по поверхности

EXPL (`ExplLib`) читает `CControlBase::CommitNdpDamageStateTransition` (Control.dll), когда деталь переходит в худшее состояние повреждения; ссылки на EXPL лежат в записях NDP, BULL и предметах CTL. Файл — 0x18 байт заголовка и 12 слотов `{NRes archive[32], item[32]}` по 0x40. Игра берёт id материала поверхности, в которую попал объект (байт 4 элемента MAT0, 0..10, 255 — не задан; при попадании без треугольника — 10), и открывает слот `m + 1` (смещение `0x58 + 0x40*m`); если слот пуст или попадания нет — слот 0 (смещение 0x18). Поля: `+4` — прибавка к потерянному запасу жизни (пишется в запись активного взрыва), `+8` — множитель масштаба (для пуль — абсолютный масштаб, для остальных — умножается на радиус сферы детали), `+0x14` — режим направления (0 — ось Y детали, 7 — нормаль поверхности; остальные значения 1–6 в данных не встречаются), `+0`, `+0xC`, `+0x10` не читаются (`+0xC` и `+0x10` всегда 1.0).

Слоты по id материала (имя эффекта в слоте совпадает с классом материалов): 1 — камень/ландшафт (`st`), 5 — металл, роботы и здания (`m`), 6 — дерево (`w`), 7 — вода (`wb/wl/wm/wt`), 8 — `B_MTP_*` (`al`), 9 — птицы и `TOK11`/`TOK42W` (`an`), 10 — `TOK51`, `B_A_BRIGE` (`s`); ids 0, 2, 3, 4 почти не используются (слоты 1, 3, 4, 5 пусты или повторяют `exp_b_he`). Названия для 8–10 — догадка по суффиксам.

Что происходит дальше: запись активного взрыва обрабатывает `CControlBase::method_173e0` по `EXPL+0`: 2 — урон только пораженному объекту, 3 и 4 — урон по сфере всем объектам в радиусе (кроме владельца), части с флагом 0x10 получают импульс, дочерние NDP-детали обнуляются. Падающие обломки симулирует отдельно `CControlClassic::method_17880`. Значения `EXPL+0` — вывод по ветвлениям кода, на данных не проверен.

Единственный найденный запуск FXID прямо из кода: `iron3d.dll` создаёт `env_mineral` для каждого месторождения на карте (`FUN_10093170` открывает `effects.rlb`/`env_mineral` через `IEffectManager`, `FUN_10093760` для каждого месторождения вызывает `LoadNResEffectItem` с id = номер месторождения, `DeactivateEffect`, `SetEffectTransform` в мировом пространстве (высота ландшафта + 17.5), масштаб 3.0 и `StartEffect` с источником силы `Life_Fract`). Это подтверждает, что id эффекта выбирает вызывающий код, а не файл.

Второй запуск из кода — молния: `CreateAtmosphereObject` (Terrain.dll) создаёт по типу объекта атмосферы Sun (0), Sky (1), Rain (2), Snow (3) или Lightning (4). `CLightning::ctor` (0x10045090) открывает `effects.rlb`, берёт имя эффекта из переданной ссылки на ресурс атмосферы, загружает его с id 0 и сразу делает `DeactivateEffect`. Имя лежит в `sky.ske` миссии (`SkeLib`): у записей типа 8 первая из четырёх строк — `env_lightning`; так это имя встречается в `sky.ske` миссий CAMPAIGN.03 (01–04) и Multi.03 (ссылка из распакованных данных не находилась, потому что `MISSIONS` не распаковывается). Строка `env_lightning` в самой Terrain.dll — значение по умолчанию в таблице параметров, которую заполняет функция 0x10044d50 (статическая инициализация, поэтому на неё нет xref). Поиск всех 476 имён FXID по остальным файлам игры (819 файлов без DLL и архивов) других ссылок не дал.

Типы записей `sky.ske` (`CAtmData::GetEvents`): 0 и 1 — создание и удаление Sun (имя записи `sun` или `moon` выбирает тело), 3 и 4 — Rain (первая строка списка — звук, обязательна), 5 и 6 — Snow, 8 и 9 — Lightning (первая строка списка — имя FXID, обязательна), 7 — просто ключ цвета неба без события. Время записи — час и минута игровых суток, которые зона растягивает на свою реальную длительность (`RealDuration`, от 0:09 до 24:00).

Между соседними записями все значения линейно интерполируются (`CAtmData::method6`, коэффициент — доля прошедшего времени между ключами) и передаются объекту по его типу: Sun получает 7 значений (слоты 0–2: цвет `Fields48[12]` × `ParamsCC[2]` — цвет основного направленного света; слоты 3 и 4: `ParamsCC[0]` и `[1]` — ширина и высота диска; слот 5: `Fields48[10]` — цвет блика, его альфа — сила ослепления (свет усиливается до ×5, когда камера смотрит на солнце); слот 6: `Fields48[14]` — цвет второго света, направленного противоположно, без бликов; если длина вектора цвета основного света больше 1.1, всем юнитам и ангарам уходит сообщение «включить/выключить» окружающий режим), Sky — 17 (слоты 0–3: `Colors30`, 4–7: `Fields48[0..3]`, 8–11: `Fields48[4..7]`, 12: `Fields48[8]`, 13 и 14: `FadeInner` и `FadeOuter`, 15 — цвет облачного слоя (`Fields48[11]`, третий проход купола, рисуется только при настройке `AtmCloudsOn`), 16: `Fields48[13]`; в `CSky` слоты 0–3, 4–7 и 8–11 — цвета четырёх секторов нижнего (горизонт, смешивается по направлению камеры, 90° на сектор), среднего и верхнего поясов купола, между секторами цвет интерполируется по кругу, слот 12 красит вершину купола и первое кольцо; `FadeInner` и `FadeOuter`, умноженные на 700, и цвет слота 16 `CSky::UpdateVertexColors` каждый кадр кладёт в `ShaderConfig` по умолчанию (`fadeInnerFactor`, `fadeOuterFactor`, `minDiffuseClamp`, flags 0x50): это дистанция затухания и нижняя граница диффузного освещения для всего, что рисует шейдер), Rain и Snow — цвет `Fields48[12]` и число `ParamsCC[3]`, Lightning — только `ParamsCC[3]`. `Fields48[9]` метод не читает (везде 0xFF000000). Название записи `sun` выбирает диск-материал 3 и орбиту 90°/30°, любое другое (луна) — материал 4 и орбиту 0°/50°; положение по дуге равно доле прошедшего времени между SunStart и SunEnd, от −0.1π до 1.1π.

## Окна компонентов: когда стартуют части эффекта

Все компоненты FXID работают от одного значения силы 0..1 (при `StrengthSource` = Life это `время / Duration`), у каждого есть окно активности. Смещение окна в файле (float, float):

| Тип | Смещение окна |
|---|---|
| 1 свет, 2 звук | 0x08/0x0C |
| 5 шлейф | 0x0C/0x10 |
| 8 спавнер | 0x10/0x14 |
| 7, 10 частицы | 0x14/0x18 |
| 3, 4, 9 объект | 0x20/0x24 |

Если конец окна меньше начала (`bld_repair_out`: 0.80-0.10), окно «заворачивается» через 1.0. Проверено по 476 файлам `effects.rlb`: у 344 есть минимум два компонента с окнами, у 150 из них начала окон отличаются больше чем на 0.01, то есть части эффекта стартуют со сдвигом. Типичные случаи:

- `exp_*` (26 файлов), например `exp_an_las_r` (1.5 с, Life): вспышка (`spittle_g`, тип 9) 0.00-0.40, звук 0.00-0.10, свет 0.00-0.50, затем капли и облако (частицы) 0.20-1.00;
- `f_*` (27), `ws_*_build_sph`, `f_build_sph`: два объекта 0.20-1.00 и 0.35-1.00, звук 0.99-1.00 (завершение сборки);
- `door_open_*`, `door_close_*`: три звука 0.00-1.00, 0.00-0.05 и 0.95-1.00 (начало/конец), `Duration` = 0, источник силы 16/17 (прогресс анимации части);
- `rl_*`, `rm_*`, `rb_*`, `rtr_*light*` (огни): объект 0.00-1.00, затем 0.50-1.00 (или 0.75-1.00) и свет 0.75-1.00;
- `bld_repair_out` (5 с): девять объектов, окна 0.0-0.2, 0.1-0.3, ... 0.8-0.1 — «бегущая» волна со сдвигом 0.1.

Остальные 326 файлов: либо один компонент с окном (132 файла), либо все окна начинаются в одно время (например, щит: звук и плоскость 0.01-0.99).

## Проигрыватель эффектов (NResUI, панель «Effect Player»)

Код: `NResUI/EffectPlayer/*` (`EffectAssetCache`, `EffectSimulator`), `NResUI/ImGuiUI/EffectPlayerPanel.cs`, состояние: `NResUI/Models/EffectPlayerViewModel.cs`. Нужен `config.json` с `GameBasePath`: из папки игры читаются `effects.rlb`, `Material.lib` и `Textures.lib`.

Что умеет:
- список FXID с фильтром, воспроизведение/пауза/повтор/скорость, перемотка по времени и мышью по таймлайну;
- таймлайн окон активности: по строке на компонент, полоса = окно на значении силы 0..1 (окна, где конец меньше начала, рисуются двумя частями), курсор = текущая сила;
- режимы силы: `Life` (время / длительность, как `StartEffect(handle, 1)`), «из заголовка» (только для временных источников; остальные показываются как `Life`) и ручной ползунок для источников, зависящих от состояния игры;
- превью с ортографической камерой (кнопки Сбоку/Спереди/Сверху и ползунки поворота и наклона; штрихи частиц ориентируются по проекции скорости и укорачиваются, когда летят вдоль луча взгляда, облака и объекты остаются спрайтами, обращёнными к экрану): спрайты типов 3/4/9 (позиция и масштаб по жизни окна, прозрачность по `LifeLerp`), частицы типов 7/10, источники света (мягкие круги), маркеры для шлейфа и спавнера; звук (см. ниже); кадры материала берутся из `MAT0` (ключи как время окончания стадии, режимы Loop/PingPong/Clamp, цвет = Ambient, страница атласа = `TextureStageIndex`).

Упрощения (превью, не копия рендера): 3D ориентация объектов и камера игнорируются (размер спрайта = среднее геометрическое двух наибольших компонент масштаба); частицы без настоящей симуляции траектории (линейная интерполяция по жизни + случайный бокс + гравитация `g·t²/2`, не более 256 частиц на компонент); спавнер и шлейф отображаются только в таймлайне/маркерами; смешивание стандартное (alpha), игра для эффектов, вероятно, использует аддитивное (полностью непрозрачные не-8888 текстуры получают альфу из яркости, что на тёмном фоне близко к аддитивному). Форма спрайтов в текстурах формата 8888 (`WAVE.0`, `EFFECT4.0`, `EFFECT5.0`) хранится в альфа-канале: `TexmFile.GetRgba32BytesFromMipmap(..., preserveAlpha: true)` возвращает его (по умолчанию альфа принудительно 255, как раньше), свет рисуется компактным свечением, а не областью освещения. Окно ImGui работает по событиям, поэтому во время воспроизведения панель переключает `IsEventDriven` в `false`.

Звук (`EffectSoundPlayer`, только Windows: `winmm.dll`, `waveOut*`): WAV (PCM) берутся из `sounds.lib` по `Resource` компонента типа 2. Одиночные звуки (`Mode` не 2/3) запускаются при пересечении начала окна силой снизу вверх, зацикленные (`Mode` 2 и 3, `EffectSoundData.IsLooped`) звучат, пока сила внутри окна, и останавливаются при выходе из окна, паузе и перемотке. Громкость = `lerp(VolumeStart, VolumeEnd, сила)` × ползунок «Громкость». Каждый звук получает своё устройство `waveOut`, поэтому звуки смешиваются системой и перекрываются. 3D позиция, затухание по расстоянию (`MinDistance`/`MaxDistance`) и «звуки в окне при перемотке» не моделируются; не-PCM WAV пропускаются с предупреждением.

### Фаза кадра материала и форма спрайта (проверено по Effect.dll)

- Кадр анимированного материала выбирается не по времени, а по **фазе** 0..1: `EffectType3::RenderContents` считает `v = pow(t, PhaseExponent) * (PhaseEnd - max(PhaseStart, 0)) + max(PhaseStart, 0)` (`t` = сила эффекта при `PhaseStart < 0`, иначе нормированная жизнь в окне), передаёт в `EffectContents::Draw` дробную часть `v - floor(v)`; `Draw` ограничивает её 0..1 и отдаёт менеджеру материалов вместе с handle материала. У частиц (типы 7/10, `EffectType7::Render`) фаза = `(значение окна - сдвиг группы)`, делённое на `RepeatRate` при `RepeatRate <= 1`, иначе дробная часть произведения; значения ≥ 1 заменяются на 0.99.
  Следствие: `PhaseEnd = 9` при источнике силы «скорость» прокручивает анимацию материала 9 раз по диапазону скорости; у одностадийных материалов (`jet3`) фаза ни на что не влияет.
- `ESpace` определяет форму: 0 (`MESH`) - свободный билборд к камере; 1 (`LOCAL`) - осевой билборд: вытянут вдоль `Direction` на `Scale.X`, шириной `Scale.Y`, разворачивается вокруг этой оси к камере (типичный факел двигателя `engine_mis_h`: `jet3` space 0 размер 5 в начале координат + `jet4` space 1, центр X 5 → 10, длина 10 → 20, ширина 2); 2 (`WORLD`) - плоскость с нормалью `Direction` и размерами `Scale.Y` × `Scale.Z` (кольцо щита).

### Шлейф (тип 5) и смешивание (проверено по Effect.dll / World3D.dll)

- `EffectType5::Render` рисует **отрезок** `start_point` -> `end_point`. `end_point` - текущая позиция привязки, обновляется каждый кадр. `start_point` запоминается при первом `EvaluateAtTime` внутри окна (позиция при старте). Сообщение `NotifyAttachPointMoved` (`FRAME_UPDATE` -> `OnAttachPointMoved`) сбрасывает его каждый кадр только если эффект привязан через `UpdateCachedLocalPoint` (`attachedToGameObjectID != 0`, флаг `0x1000` лишь включает рассылку); у эффектов, созданных командами CTL, этого нет, и шлейф тянется от точки старта. Хвост не укорачивается: число кусков = `floor(длина / MaxPieceLength)` в пределах `1..MaxPieces` (20), при превышении куски растягиваются.
- Жизненный цикл лазерного луча (`las_tail_*`, источник Constant, окно 0..1, значение 1 -> 0, длительность 0.75 с; подтверждено наблюдением в игре): эффект создаётся при загрузке снаряда с константной силой 0 (окно содержит 0, значение = `ValueStart` = 1, луч виден целиком от орудия до снаряда), при попадании CTL снаряда запускает его командой `START_EFFECT` с источником Life, и за 0.75 с значение падает 1 -> 0 (луч плавно затухает на месте); снаряд живёт ещё `DetachCleanupDelayMs` (1000 мс), поэтому затухание успевает закончиться. У шариковых снарядов в этих состояниях эффект выключается (`DEACTIVATE_EFFECT`).
- Ширина куска = `lerp(WidthStart, WidthEnd, окно)`, значение (прозрачность) = `lerp(ValueStart, ValueEnd, окно)`; текстура повторяется каждые `TextureTileLength`, сдвиг = `frac(scroll)` (при `TextureScrollEnd < 0` - случайный сдвиг каждый кадр).
- Скорость снаряда в FXID не хранится, в проигрывателе это ползунок «Скорость шлейфа».
- Смешивание в MAT0 нет отдельным полем: байт 4 элемента (раньше `SourceBlendMode` в Ghidra) - класс поверхности. Единственное, что `LoadMaterialByName` передаёт устройству о «типе» материала, - `wanted_device_caps = (version >> 2) & 0xF`. Материалы эффектов (`JET*`, `LIGHT1`, `LASER_R`, `GLOW_R`, ...) имеют `version = 8`, то есть caps = 2 («particle»); 0 - обычные (стены, техника), 1 - небо/EXPL/SHOOT. Сам режим выбирает рендерер (Ngi32.dll, в Ghidra не открыт), поэтому проигрыватель считает **materials caps = 2 аддитивными** (`src*a + dst`), остальные - обычным alpha-смешиванием; режим переключается в панели («Смешивание»). Это вывод по данным и визуальным признакам (чёрный фон эффектов, непрозрачные текстуры `WAVE.0`, `EFFECT4.0`), а не прочитанная константа.
- Холст проигрывателя собирается собственным GL-рендером в offscreen-текстуру (`NResUI/EffectPlayer/EffectCanvasRenderer.cs`): ImGui рисует только alpha-смешиванием.

### Просмотр орудий

Панель `Weapon Viewer` (`NResUI/ImGuiUI/WeaponViewerPanel.cs`) проигрывает выстрел целиком: эффекты CTL орудия (вспышка, звук, дым) стартуют в момент выстрела в начале координат; эффекты CTL снаряда движутся вместе со снарядом со скоростью `MaxTangentialSpeed.Y` (шлейф тянется от дула до снаряда и ограничен дистанцией); через `дистанция / скорость` снаряд исчезает и в точке цели запускается эффект EXPL (слот выбирается по материалу поверхности). Источник силы всех эффектов - время (`Life`), у эффектов снаряда жизнь повторяется по длительности. Список эффектов с командами (`список`, `код`, `local_id`) и слотами EXPL показывается в панели.
Не моделируется: траектория, разброс, ускорение ракеты (скорость постоянна), поворот ствола, модель орудия и снаряда.

### Спавнер (тип 8) и отцепление эффекта (проверено по Effect.dll)

- **Спавнер** (`EffectType8`, ресурс - материал; `smoke_rk_01`, `smoke_ms_01/02`, `smoke_rail`, 4 файла: источник силы 5, то есть доля скорости, окно 0.5..1.0, интервал 0.05 -> 0.02 с, кольцо 25 или 75 частиц). Пока значение силы в окне, каждые `interval = lerp(SpawnIntervalStart, SpawnIntervalEnd, окно)` секунд в точке привязки создаётся частица, которая **остаётся в мире** (мировая матрица слота с осью X по направлению движения); возраст = место в кольце / `MaxParticles`, живёт `MaxParticles * interval` секунд (0.5-4 с). Траектория и размер идут от `Start` к `End` по возрасту (со случайным разбросом `SpawnBox` / `SizeJitterBox`), значение (прозрачность) - `ValueLerpStart` -> `End`. Получается дымовой след за ракетой. Проигрыватели NResUI рисуют его.
- **Флаг 0x4 (`DetachAfterEmit`)**: после первого обновления `UpdateEffectHandle` вызывает `ResetTransformToParent` и снимает привязку к детали - эффект остаётся там, где был создан. Так сделаны облака у дула (`gunf_missile_*`, `gunf_*`: частицы типа 7 длительностью до 5 с): ракета улетает, облако висит у дула.
