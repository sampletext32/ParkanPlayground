# MaterialLib: материалы, наборы (WEA), текстуры

![Material Explorer: материал `B_PG3` - поля MAT0 в порядке чтения из файла](../docs/images/material-explorer.png)
*Material Explorer: материал `B_PG3` - поля MAT0 в порядке чтения из файла*


Что делает `MatManager` (World3D.dll) и как игра использует данные `Material.lib`, `Textures.lib`, `lightmap.lib`, `.wea`.
Адреса относятся к World3D.dll (база 0x10000000), если не сказано иное. Имена и структуры - в проекте Ghidra.

> **Кратко.** Материал MAT0 из `Material.lib` - набор стадий (цвета и текстура) и анимаций, которые переключают стадии по времени или по фазе 0..1.
> Версия материала задаёт режим смешивания (непрозрачный / alpha-test / аддитивный), байт класса поверхности выбирает слот взрыва EXPL и хуки CTL, а два
> числа в конце задают скорость и потерю жизни юнита на поверхности. Набор материалов объекта собирает текстовый `.wea`. Подробности полей и статистика - в
> XML-комментариях `MaterialFile`, `MaterialStage`, `MaterialAnimation`, `AnimationTarget`, `AnimationLoopMode`, `MaterialBlendMode`, `SurfaceMaterial`.

## 1. Цепочка загрузки

| Шаг | Функция | Что делает |
|---|---|---|
| 1 | `MatManager::LoadWear(nres_path, name)` (0x10003DC0) | открывает NRes и берёт элемент `name` (если задан `nres_path`) либо читает текстовый файл `name` (`fopen "rt"`) |
| 2 | `MatManager::LoadWearSetFromWeaText(text)` (0x10004250) | разбирает текст WEA (то же, но из памяти); `FxManager` использует его для однострочных наборов (`GetOrLoadMaterialHandle`) |
| 3 | `LoadMaterialByName(name)` (0x10004630) | находит материал в `Material.lib`, разбирает MAT0 в `MaterialGlobalDescriptor` (0x170 байт), возвращает индекс дескриптора |
| 4 | `LoadAndCacheTexture(name, flags)` (0x10004E40) | загружает текстуру стадии из `Textures.lib` (TEXM) через `I3DRender::CreateTexture`; кэш по индексу элемента |
| 5 | `LoadAndCacheLightmapTexture(name, flags)` (0x10004FE0) | то же для `lightmap.lib` (флаг 0x200000) |
| выгрузка | `UnloadMaterial(index)` (0x10003160), `UnloadAllTextures` (0x10003260) | уменьшают счётчик ссылок, освобождают ключи анимаций и стадии |

При создании первого менеджера (`g_matmanagers_created_count == 0`) открываются `g_texture_resfile`, `g_material_resfile`, `g_lightmap_resfile` и обнуляются кэши. `PreLoadAllTextures` (0x100032C0) - пустая функция.

Идентификатор материала для менеджера упакован: `(номер набора << 16) | номер материала в наборе`; идентификатор карты освещения - так же.

## 2. Формат MAT0

Элемент `Material.lib`: NRes-метаданные `attr1` = `version`, `attr2` = `Magic1`. Содержимое (порядок чтения, `LoadMaterialByName`):

| Что | Когда читается | Смысл |
|---|---|---|
| `stageCount` u16, `animCount` u16 | всегда | `animCount` ≤ 19 (иначе ошибка «Too many animations») |
| класс поверхности u8, байт 5 u8 | `Magic1 >= 2` | класс - `SurfaceMaterial` (EXPL, звуки), байт 5 в данных всегда 255 |
| `surface_speed_scale` float | `Magic1 > 2` | множитель скорости юнита на поверхности (§7) |
| `surface_life_drain_per_sec` float | `Magic1 > 3` | потеря жизни юнита в секунду на поверхности (§7) |
| стадии `stageCount` × 34 байта | всегда | ambient RGB + A·0.01, diffuse RGBA, specular RGBA, emissive RGBA (всё /255), Power u8, индекс страницы TEXM u8, имя текстуры[16] (пустое → без текстуры) |
| анимации `animCount` | всегда | u32 `(FieldSelector << 3) \| loop_mode`, u16 число ключей, ключи u16 стадия / u16 конец интервала в мс / u16 кривая (всегда 0) |

Биты `version` (`element_count_or_version`):

| Биты | Смысл |
|---|---|
| 0 (1) | при загрузке текстур флаг 0x200000 (в данных только у `ENV_STARS`) |
| 1 (2) | поддерживает bump (`extra_meta.bump_mapping_flag`); без bump у устройства - флаг текстур 0x80000 |
| 2..5 | **индекс режима смешивания** (§6) |
| 6 (0x40) | `extra_meta.version_flag_0x40` (в данных не встречается) |

Версии в данных: 0 (53 материала), 2 (324), 4 (183), 5 (1), 8 (67); `Magic1` у всех 6.

## 3. Набор материалов `.wea`

Текст (CRLF), файл или элемент NRes:

```
{N}
{индекс} {имя материала}      N строк
LIGHTMAPS                     необязательный раздел
{M}
{индекс} {имя карты освещения}   M строк
```

| Факт | Подробности |
|---|---|
| Номер строки не используется | загрузчик читает число и отбрасывает; материалы идут по порядку строк, номер в наборе = порядковый номер |
| Раздел `LIGHTMAPS` | сравнивается без регистра, если нет - карт освещения нет |
| Ограничения | менеджер хранит до 40 наборов (`material_ptrs_by_wea[40]`, `lightmaps_indices_by_wea[40]`) |
| Файлы | 414 `.wea` в данных; наборы объектов, ландшафта, неба и однострочные наборы эффектов |

Для каждого материала набора хранится `{handle, lastUsedTime}` (`WearMaterialRef`, 8 байт): `lastUsedTime` ставится в `g_game_time` при загрузке и в `UpdateMaterialLastUsedAt` (0x10003D90); от него считается время анимации (§5).

## 4. Кэши и счётчики ссылок

| Кэш | Размер | Запись | Правила |
|---|---|---|---|
| `g_textures_cache` | 777 | `CacheEntry` (20 байт): `index_in_file`, `m_LL_ITexture`, `refCount`, `metadata`, `texture_flags` | поиск по `index_in_file`, при совпадении `refCount++`; свободный слот - `refCount == 0 && metadata == 0`; при `refCount → 0` в `metadata` пишется время выгрузки (`g_game_time`), сама текстура не освобождается до `UnloadAllTextures` |
| `LightMaps_cache` | 100 | то же | то же |
| `g_MaterialGlobalDescriptors` | - | 0x170 байт | поиск по `index_in_file`, `RefCount` |

Палитра текстуры выбирается по суффиксу имени после точки: `палитра = (toupper(c1) - 'A') * 11 + (c2 - '0' + 1)` (c2 нет → +0); индекс < 0 → без палитры (верхняя граница не проверяется, `g_palettes` - 6 элементов). В `Textures.lib` (296) и `lightmap.lib` (25) все имена оканчиваются на `.0` → палитры (`Palettes.lib`, `g_palettes[6]`) не используются.

## 5. Выбор стадии: анимация материала

Кадр материала не берётся из «текущего» состояния: стадию вычисляют по времени или по фазе (подробности применения у моделей - `ControlLib/README.md`, §7.8).

| Метод | Функция | Как считает |
|---|---|---|
| по времени | `MatManager::AnimateFrame(material, animation_index)` (0x10003490) | `t = (g_game_time - lastUsedTime) % duration` (`duration` - конец последнего ключа); ключ `k` действует до своего `duration_ms`; соседние стадии смешиваются |
| по фазе | `MatManager::GetMaterialPhase(material, animation_index, phase)` (0x10003930) | `t = phase · duration` (фаза 0..1, вне диапазона → 0.5) |

`loop_mode` (биты 0..2 слова анимации): 0 - цикл, 1 - ping-pong, 2 - один раз, 3 - случайная позиция. Подробности по `AnimateFrame`: в режиме 2 после конца анимации начальным ключом берётся последний, позиция 0, следующий - ключ 0, поэтому доля `(0 - начало) / (конец - начало)` отрицательна и цвета по маске экстраполируются от последней стадии (у `SPLASH2`, `SPITTLE_G`, `EXPL3`, `EXPL4`, маска 1; результат насыщается в 0..1); в режиме 3 каждый вызов берёт `rand() % длительность` без привязки ко времени (в данных один раз: `DEFL_G`, 4 стадии по 5 мс, маска 1; NResUI привязывает случайность к кадру времени). `animation_index` вне `0..animCount-1` заменяется на 0. Если ключей меньше 2 - берётся стадия первого ключа без смешивания.

`Interpolate(src1, src2, progress, dst, FieldSelector)` (0x100032D0): биты `FieldSelector` - 1 ambient RGB, 2 diffuse RGB, 4 specular RGB, 8 emissive RGB, 0x10 ambient.A (прозрачность/яркость материала). Не выбранные компоненты копируются из начального ключа; **Power не интерполируется никогда** (берётся из начального ключа); A-каналы diffuse, specular и emissive не копируются вовсе - в анимированных материалах не используются.

В данных: `R_GB50`, `R_GB51`, `R_GB52` - 4 стадии по 50 мс (цикл 200 мс) = кадры свечения ствола; `R_GB16` - то же, ping-pong; `R_LBL_01`/`B_LBL_01` - 8 анимаций по одному ключу (выбор варианта индексом анимации); 43 материала `L*` (ландшафт) - 2 стадии, 2 анимации; остальные 583 - одна анимация.

В данных 76 анимаций с ненулевой маской и ≥ 2 ключами (`FieldSelector`: 1 - 68, 3 - 3, 7 - 3, 17 - 1, 2 - 1): `JET8`, `JET9`, `SPLASH2`, `DUST`, `SMOKE`, `LASER_G`, `B_MN_01R/G/B`, `B_S13`, `R_RLW_5`... Цвета у них плавно переходят от стадии ключа к стадии следующего ключа, текстура берётся из стадии начального ключа. Реализация в NResUI: `MaterialAnimator.Sample` / `SampleByPhase` (`NResUI/EffectPlayer/MaterialAnimator.cs`), применяется в `EffectAssetCache.TryGetSprite`.

Граничный случай: позиция, не попавшая ни в один интервал (в частности фаза ровно 1.0, `position = duration`), даёт стадию первого ключа, а не последнего.

## 6. Режим смешивания

Биты 2..5 `version` = индекс профиля состояний рендера Ngi32 (`g_DefaultRenderStateProfiles`): 0 непрозрачный; 1 SRCALPHA/ZERO + alpha-test; 2 SRCALPHA/ONE (аддитивное; материалы эффектов `JET*`, `LIGHT1`, `LASER_R`, `GLOW_R`); 3 ZERO/SRCCOLOR; 4 SRCALPHA/INVSRCALPHA; 5 DESTCOLOR/SRCCOLOR. В данных только 0, 1, 2. Таблица и цепочка вызовов - `FxidLib/README.md`, «Материалы и смешивание».

## 7. Свойства поверхности

`MatManager::GetMaterialSurfaceClassPtr` (0x10003D60) отдаёт 4 слова дескриптора:

| Слово | Поле | Смысл | Данные |
|---|---|---|---|
| 0 | `surface_material_class` | класс поверхности: слот EXPL при попадании, класс для хуков 10..20 юнита | 0..10 или 255 |
| 1 | `unk_byte5_TBD` | назначение неизвестно | всегда 255 |
| 2 | `surface_speed_scale` | множитель скорости юнита на поверхности (`runtime_tangential_speed_scale`) | 1.0 у всех |
| 3 | `surface_life_drain_per_sec` | потеря жизни юнита в секунду (`passive_life_drain_rate`) | `ENV_LAVA_BOT`, `WATER_BOT` 10000; `B_S0_DAM`, `B_DD1DK_DAM` 1000; остальные 0 |

Читает `CControlClassic::BTLU_frame_update` (Control.dll 0x1001F1C0); при смене класса под юнитом выполняется хук-список `10 + класс`.

## 8. Чего нет в данных

- Режимы смешивания 3, 4, 5; бит версии 0x40; кривая ключа (`InterpolationCurve` всегда 0).
- Палитры текстур: ни у одной текстуры суффикс не выбирает палитру.
- Множитель скорости поверхности ≠ 1.0.
- Байт 5 элемента MAT0 всегда 255.
