# RsLiLib: NL-архивы («RsLi»)

Чтение архивов формата **NL**: плоский список именованных записей, каждая упакована своим способом. Игра называет формат «RsLi» (сигнатура в памяти
`"RsLi"`, функции `rsOpenLib`, `rsLoad`, `rsFind`, `rsGetInfo`, `rsGetPackMethod`, `rsLoadPacked` в `Ngi32.dll`). В первой части так хранятся только
два файла:

| Файл | Записей | Что внутри |
|---|---|---|
| `gamefont.rlb` | 2 | `PAL.PAL` (палитра, 66564 байта), `ARIALTEX.TFT` (шрифт, сигнатура `Tfnt`); способ LZSS |
| `sprites.lib` | 24 | текстуры `*.TEX` (сигнатура `Texm`, формат - [TexmLib](../TexmLib/README.md)); способ deflate |

Остальные ресурсы - NRes ([NResLib](../NResLib/README.md)). Библиотека собрана по декомпиляции `Ngi32.dll` (`rsOpenLib` 0x10013760, `rsLoad` 0x10013C60,
`rsFind` 0x10014010) и проверена на обоих файлах: все 26 записей распаковываются, размер совпадает с заявленным, внутри валидные `Texm`/`Tfnt`.

## Формат

```
0x00  "NL", 0x00, 0x01      сигнатура и версия
0x04  int16                 число записей N
0x0E  uint16                0xABBA: таблица записей уже отсортирована по имени
0x14  uint32                ключ XOR-шифра таблицы (младшие 16 бит)
0x20  N * 32 байта          таблица записей, зашифрована
...                         данные записей
-6    "AO", int32           необязательный хвост: смещение архива внутри файла (только при открытии с флагом 2)
```

### Запись (32 байта, после расшифровки)

| Смещение | Размер | Поле | Описание |
|:--:|:--:|---|---|
| 0x00 | 12 | `Name` | имя, верхний регистр, до 12 символов, завершается нулём (при загрузке игра обнуляет следующие 4 байта: имя - 16 байт) |
| 0x0C | 4 | `Unknown0C` | не читается; значения выглядят случайными |
| 0x10 | 2 | `MethodFlags` | способ упаковки: биты 0x1E0 |
| 0x12 | 2 | `SortIndexOrKey` | индекс в порядке сортировки по имени (по нему `rsFind` делает бинарный поиск); для XOR-способов `rsLoad` берёт из него же ключ |
| 0x14 | 4 | `UnpackedSize` | размер распакованных данных |
| 0x18 | 4 | `DataOffset` | смещение данных от начала файла |
| 0x1C | 4 | `PackedSize` | размер данных в файле |

### XOR-шифр

Один и тот же шифр защищает таблицу и данные с XOR-способом. Состояние - два байта: `x` (младший байт ключа) и `y` (старший):

```
g = ((x << 1) ^ y) & 0xFF
x = g
y = ((y >> 1) ^ g) & 0xFF
out[i] = in[i] ^ g
```

### Способы упаковки

| `MethodFlags & 0x1E0` | Способ | Проверено |
|:--:|---|---|
| 0x000 | без упаковки | по коду |
| 0x020 | XOR | по коду; в данных нет |
| 0x040 | LZSS: окно 4096 байт, заполнено пробелами, позиция записи 0xFEE, флаги младшим битом вперёд, ссылка - 12 бит позиции + 4 бита длины − 3 | **на данных** (`gamefont.rlb`) |
| 0x060 | XOR, затем LZSS | по коду; в данных нет |
| 0x080 | LZHUF (LZSS + адаптивный Хаффман, F = 60, 314 символов; `LzHuf_InitTables` 0x10015470, `LzHuf_UpdateModel` 0x1001553E) | по коду; в данных нет |
| 0x0A0 | XOR, затем LZHUF | по коду; в данных нет |
| 0x100 | сырой deflate (в коде игры - Info-ZIP inflate: `Inflate_Block` 0x100153A0, `Inflate_HuftBuild` 0x10014310) | **на данных** (`sprites.lib`) |

Реализации LZHUF и XOR сверены с кодом игры по структуре, но проверить на реальных данных их нельзя: файлов с такими записями в первой части нет.

## Наблюдения

- У последней записи `sprites.lib` (`INTERF8.TEX`) `DataOffset + PackedSize` на 1 байт больше размера файла: игра читает через отображение в память и этого не замечает,
  `RsLiArchive.Extract` обрезает данные по концу файла.
- `rsOpenLib` сортирует записи по имени, только если в заголовке нет 0xABBA; в обоих файлах метка стоит.
- Имена записей в архиве - не более 12 символов, `rsFind` приводит искомое имя к верхнему регистру и копирует не более 16 байт.

## API

```csharp
var archive = RsLiArchive.Read("sprites.lib");
foreach (var entry in archive.Entries)
    File.WriteAllBytes(entry.Name, archive.Extract(entry));
```

Консольная утилита - [NLUnpacker](../NLUnpacker/README.md).

## Что не выяснено

- смысл поля `Unknown0C`;
- когда XOR-способ использует `SortIndexOrKey` как ключ, если таблица отсортирована (поле тогда уже занято индексом): в данных таких записей нет.
