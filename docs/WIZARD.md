# Wizard.dll: арбитр управления объектом

`Wizard.dll` (проект Ghidra `parkan1`, 275 функций; единственный экспорт `CreateWizard`, интерфейс `IWizard` = 0x201) - небольшая библиотека. Её класс
`CWizard` (0x224 байта) создаётся для игрового объекта и решает, кто им управляет, а также ведёт объект по очереди точек движения, когда команды приходят
извне (по сети). Название - внутреннее; в данных игры оно не встречается.

Реализует `IWizard`, `INetSerializable` (0x26) и `IComponent`; при `GMSG_INIT` запрашивает у своего объекта `IGameObject`, `IControl`, `ILifeSystem`,
`IManManager`, `IItemManager`, `IBehaviour`.

## Режим управления

Поле `control_mode` (`+0x200`):

| Значение | Режим |
|:--:|---|
| 0 | управляет поведение (`IBehaviour`, ИИ) |
| 1 | управляет «человек» (`IManManager`, ручное управление) |
| 2 | выключено (`movement_disabled`) |

Режим меняется сообщением `_GMSG_SET_STATE`. Для каждой подсистемы есть переопределение (`SetProperty`, маска `+0x204..+0x220`): 0 - по режиму,
1 - принудительно поведение, 3 - принудительно человек. Подсистемы - движение (две маски: 1 и 2) и предметы объекта по типу (0..5; тип предмета
возвращает `IItemManager` - значения 4, 5, 2, 0, 3, 1 привязаны к маскам `0x20`, `0x10`, `0x40`, `0x80`, `0x100`, `0x200`). `UpdateWizardState`
(0x10003B20) пересчитывает итог и сообщает `IBehaviour` и `IManManager`, какие предметы и оси им разрешены.

## Движение по очереди точек

Если движением не управляет «человек», Wizard само ведёт объект к точкам `MovementPoint` (44 байта: позиция, линейная скорость, касательная курса,
`time_ms`, `flags`). Точки приходят через `QueueMovementPoint` (0x10001EC0), очередь очищает `ClearMovementQueue`, запасную цель задаёт
`SetFallbackTarget` (принимается, если она дальше 0.5 от прежней). Каждое из трёх действий добавляет событие в `outgoing_net_events` (типы 1, 2, 3) для
сетевой синхронизации. Методы `AppendMovementPoint`, `InsertMovementPoint`, `DeleteMovementPoint` - заглушки с фатальной ошибкой «Wizard panic».

Порядок за такт (`UpdateMovement`, 0x10001E00; не работает, если в `stdGetGameMode()` установлен бит 2):

1. `AdvanceMovementSegment` (0x10002E50) при выходе за `time_ms` целевой точки берёт следующую из очереди (или запасную цель, или стоп на 1 с)
   и строит кубическую кривую Эрмита по позиции и по курсу (`CubicCurve::SetHermite`), длительность сегмента `segment_duration_sec`.
2. `EvaluateMovementAtTime` (0x10003390) считает позицию, скорость и курс в текущий момент; курс - либо кривая, либо линейная интерполяция, если у
   целевой точки флаг `MOVEMENT_POINT_FLAG_LERP_FACING`.
3. `ApplyMovementControlCommands` (0x100039D0) переводит скорость в локальные оси объекта и записывает её в `IControl` (`SetTangSpeed`,
   `SetNormSpeed`); поворот по оси Z - `ComputeAxisRotationCommand` (угол между текущим и нужным курсом, делённый на допустимую скорость поворота,
   не более 1). Флаги точки по четыре бита на ось (`flags >> 4`, `>> 8`, `>> 12`): 1 - только вперёд, 2 - только назад, оба - ноль, 4 - постоянная
   максимальная скорость из свойства управления.

## Не выяснено

- `named_array_0x10` (очищается сообщением 0xB);
- смысл `CWizard::method14` (предмет, свойство `0x54`, `0x400`);
- точные значения битов флагов `MovementPoint` кроме перечисленных;
- кто вызывает `QueueMovementPoint` (сеть: `Net.dll` не разобран).
